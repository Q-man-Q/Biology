# Техническое описание технологий и архитектуры информационной системы «ЭкоКарта Заказника Эбита»

> **Назначение документа:** Полное научно-техническое описание технологий, архитектуры и этапов разработки специализированной веб-геоинформационной системы (Web-ГИС) «ЭкоКарта Заказника Эбита» (*Ebita EcoMap*) для использования в дипломной работе, научной публикации или отчете о научно-исследовательской работе (НИР).

---

## Паспорт проекта
* **Наименование системы:** ЭкоКарта Заказника «Эбита» (*ebita-boundary-editor / Ebita EcoMap*).
* **Объект исследования:** Государственный природный заказник «Эбита» (Тереклинский и Эбитинский участки, 13 лесных и степных кварталов).
* **Предметная область:** Экологический мониторинг териофауны (млекопитающих), пространственный анализ встреч животных по типам ландшафтных биотопов, цифровая инвентаризация границ ООПТ.
* **Тип приложения:** Кроссплатформенная веб-ГИС (Single Page Application, SPA) с архитектурой Offline-First и облачной синхронизацией.

## 1. Картографическая основа и геопространственные данные

Картографический модуль приложения решает задачу точной пространственной локализации биологических объектов в полевых и камеральных условиях.

### 1.1. Картографические подложки (Tile Providers)
* **Google Satellite + Hybrid Layer:** Высокодетализированные спутниковые ортофотопланы земной поверхности с координатной привязкой и гибридным векторным слоем гидрографии и топонимов (`https://mt1.google.com/vt/lyrs=y&x={x}&y={y}&z={z}`). Обеспечивает возможность детальной дешифровки рельефа, растительных комплексов и мест обитания животных до 20-го уровня масштабирования (`maxZoom: 20`).
* **OpenStreetMap (OSM) & Esri World Imagery:** Предусмотренная архитектурная интеграция альтернативных картографических основ (топографическая векторная карта OSM и глобальные космические снимки Esri).

### 1.2. Геопространственные данные заказника «Эбита»
* **Система координат:** Общепринятая международная эллипсоидальная геодезическая система **WGS 84 (EPSG:4326)**, выраженная в десятичных градусах широты и долготы (`latitude`, `longitude`) с точностью до 6 знаков после запятой (погрешность менее 10 см на местности).
* **Сектора и квартальная сеть (13 кварталов):**
  * Векторные полигоны кварталов, разделенные на **Тереклинский** и **Эбитинский** участки заказника.
  * Хранение геометрии кварталов в стандартизованном формате JSON/GeoJSON (`ebita_reserve_boundaries.json`).
* **Внешняя граница периметра (Outer Boundary):**
  * Замкнутый контур внешнего периметра заказника.
  * Разработан алгоритм автоматической генерации внешнего периметра из примыкающих кварталов (`computeOuterBoundaryFromQuarters`), основанный на анализе топологического графа смежности (выборка уникальных ребер с кратностью вхождения 1).
* **Математический аппарат калибровки и привязки (GIS Calibration):**
  * Модуль аффинных и проективных преобразований (`pctToLatLng` / `latLngToPct`) для пересчета относительных координат архивных бумажных картосхем (`x%`, `y%`) в реальные географические координаты WGS 84 с учетом параметров масштабирования (`scaleLat`, `scaleLng`), географического сдвига (`shiftLat`, `shiftLng`) и базового диапазона координат:
    * Диапазон широт: от $51.00^\circ$ N до $51.16^\circ$ N;
    * Диапазон долгот: от $58.05^\circ$ E до $58.48^\circ$ E.
* **Топологическое замыкание (Topological Snapping):**
  * Алгоритм автоматического устранения зазоров и взаимных перекрытий (slivers) между смежными полигонами кварталов (`snapQuarterPolygons`) с использованием кластеризации вершин по методу непересекающихся множеств (Union-Find) и ортогональной проекции точки на отрезок (`pointToSegmentProjection`).
* **Пространственный анализ попадания в зону (Point-in-Polygon):**
  * Алгоритм трассировки луча (Ray Casting / `isPointInPolygon`) для автоматического определения принадлежности зафиксированного наблюдения к конкретному кварталу или сектору заказника.

## 2. Технологии разработки (Стек, языки, фреймворки)

Приложение спроектировано на базе современного стека Single Page Application (SPA):

* **Язык программирования:**
  * **JavaScript (ECMAScript 2022+ / ES Modules)** — модульная архитектура, асинхронные интерфейсы (`async/await`, промисы), деструктуризация и функциональные методы обработки коллекций данных.
* **Базовый фреймворк:**
  * **React 18 (v18.3.1)** — компонентно-ориентированная архитектура интерфейса, декларативное управление состоянием через хуки (`useState`, `useEffect`, `useRef`), эффективное обновление DOM-дерева через Virtual DOM.
* **Инструмент сборки и сборщик модулей:**
  * **Vite 5 (v5.4.2)** — сверхбыстрый инструмент сборки фронтенда нового поколения, использующий нативные ES-модули и транспайлер `esbuild`. Обеспечивает мгновенный Hot Module Replacement (HMR) в процессе разработки и оптимизированный бандлинг на базе Rollup для продакшн-окружения.
* **Картографический движок:**
  * **Leaflet (v1.9.4)** — открытая библиотека для интерактивных геоинформационных веб-карт:
    * Рендеринг тайловых спутниковых слоев;
    * Динамическое отображение векторных полигонов (`L.polygon`) с адаптивной интерактивной подсветкой (`hover`, `select`);
    * Кластеризация и расстановка маркеров наблюдений (`L.marker`, `L.divIcon`);
    * Интерактивные всплывающие карточки (`L.popup`) с информацией о фаунистических находках;
    * Модуль вершинного редактирования геометрии на карте в реальном времени с производительностью 60 FPS.
* **Стилизация и верстка:**
  * **Tailwind CSS (v3.4.10)** — утилитарный CSS-фреймворк для быстрой адаптивной верстки.
  * **PostCSS (v8.4.45) & Autoprefixer** — кроссбраузерная транспиляция и оптимизация стилей.
  * Контрастная темная цветовая тема (`slate-950`, `emerald`, `cyan`, `amber`), адаптированная для работы на открытом воздухе при ярком солнечном свете.
* **Векторная графика и иконография:**
  * **Lucide React (v0.439.0)** — комплект легковесных векторных SVG-иконок для обозначения биообъектов, следов, геометрии и статусов.

## 3. Хранение данных и архитектура работы с информацией

Система использует гибридную архитектуру **Offline-First + Cloud Synchronization**, сочетающую автономность полевого использования и надежность облачного репозитория.

### 3.1. Локальное хранение (Offline-First)
* **Web Storage API (`localStorage`):**
  * Автоматическая сериализация и сохранение ключевых сущностей в памяти браузера клиента:
    * `ebita_eco_observations` — реестр всех зафиксированных полевых наблюдений;
    * `ebita_eco_reserve_points` — актуальные векторные координаты кварталов и границ;
    * `ebita_gis_calibration` — коэффициенты калибровки картосхем;
    * `ebita_app_settings` — системные конфигурации интерфейса.
  * Обеспечивает мгновенную загрузку и полноценное редактирование данных даже при полном отсутствии мобильной связи и интернета в экспедиции.

### 3.2. Облачная база данных и синхронизация (BaaS)
* **Google Cloud Firestore (Firebase SDK v12.19.0):**
  * Масштабируемая бессерверная документная база данных (NoSQL).
  * **Реалтайм-слушатели (`onSnapshot`):** многопоточная синхронизация между устройствами исследовательской группы в реальном времени при появлении доступа к сети.
  * **Коллекции:**
    * `observations` — документы полевых находок с автоматической очисткой некорректных значений (`cleanForFirestore`);
    * `settings/reserve_points` — эталонные пространственные контуры заказника.
  * **Пакетная запись (`writeBatch`):** безопасный атомарный импорт больших объемов наблюдений без риска частичной потери данных.

### 3.3. Аутентификация и разграничение прав доступа (RBAC)
* **Firebase Authentication (Google OAuth 2.0):**
  * Вход через учетную запись Google (`signInWithPopup` с адаптивным переключением на `signInWithRedirect` при блокировке всплывающих окон браузера мобильных устройств).
  * Ролевая модель:
    * **Гость / Исследователь:** просмотр карты, аналитика биотопов, фильтрация данных;
    * **Авторизованный биолог:** внесение новых записей, редактирование собственных наблюдений;
    * **Администратор (Admin):** полный контроль над базой, редактирование контуров кварталов заказника и сброс настроек.

### 3.4. Фиксация координат и фотографий
* **Координаты:** автоматический ввод по клику на карте/полигоне квартала либо ручной ввод с полевого навигатора/смартфона.
* **Фотоматериалы:**
  * Загрузка фотографий напрямую с камеры смартфона или из памяти устройства через **HTML5 FileReader API** (`readAsDataURL`).
  * Конвертация изображений в формат **Base64 (Data URI)** и сохранение непосредственно в структуру объекта наблюдения. Это исключает зависимость от внешних серверов хранения фото при автономной работе.
  * Поддержка внешних URL-ссылок на фотоматериалы.

## 5. Функциональные возможности приложения

1. **Регистрация и паспортизация наблюдений:**
   * Создание карточки встречи животного с генерацией уникального шифра (например, `EB-749201`).
   * Фиксация даты, времени, географических координат, типа обнаружения (*визуальный контакт, следы лап, жилая нора/убежище, помет, погрызы, снимок фотоловушки, костные останки*).
   * Учет числа встреченных особей, описания половозрастного состава, типа растительности и сопутствующих полевых заметок.
2. **Специализированный биологический классификатор:**
   * Встроенный реестр видов млекопитающих степной зоны заказника «Эбита» (38 видов из 6 отрядов: *Rodentia, Carnivora, Artiodactyla, Eulipotyphla, Chiroptera, Lagomorpha*).
   * Автоматическая привязка бинарной научной латинской номенклатуры (например, *Marmota bobak*, *Saiga tatarica*, *Gazella subgutturosa*, *Lutra lutra*).
   * Выделение природоохранного статуса (фоновый, обычный, редкий, занесенный в Красную книгу).
3. **Модуль экологических биотопов:**
   * Классификатор 15 характерных биотопов заказника (разнотравно-ковыльные степи, овражно-балочные комплексы, каменистые обнажения, пойменные луга, тугайные заросли, березово-осиновые колки и др.).
   * Автоматизированный аналитический расчет плотности находок и видового богатства по каждому биотопу.
4. **Фильтрация, поиск и аналитика:**
   * Полнотекстовый поиск по русским и латинским названиям, номерам кварталов, биотопам.
   * Фильтрация в реальном времени по типу следов жизнедеятельности и экотопу.
   * Информационная панель (Footer) с динамической статистикой: общее число находок, разнообразие видов, охват биотопов, дата последней экспедиции.
5. **Интерактивный ГИС-редактор границ:**
   * Режим калибровки и ручного редактирования узлов полигонов кварталов заказника.
   * Автоматическое «прилипание» смежных границ (Snapping) для предотвращения геометрических коллизий.
6. **Экспорт, импорт и обмен данными:**
   * **GeoJSON (`.geojson`):** совместимость со стандартными настольными ГИС-пакетами (**QGIS, ArcGIS, NextGIS, MapInfo**).
   * **CSV (`.csv`):** табличный экспорт для статистического и биометрического анализа в **Microsoft Excel, R Studio, Python (Pandas)**.
   * **JSON (`.json`):** создание полного структурированного бекапа базы данных.
   * **Шеринг по URL Hash:** кодирование контуров и точек в компактную строку Base64 в хеше URL для мгновенной передачи коллегам без использования промежуточных файлов.
7. **Работа в условиях отсутствия связи (Offline):**
   * Все операции чтения, добавления и поиска функционируют локально на устройстве исследователя в степных и полевых условиях без покрытия сотовой сети.

## 6. Технологии и задачи по этапам жизненного цикла разработки

```
[Этап 1: Предпроектный анализ] ──> [Этап 2: Проектирование структур данных]
               │                                      │
               ▼                                      ▼
[Этап 3: Картографическое ядро] ──> [Этап 4: Пользовательский интерфейс]
               │                                      │
               ▼                                      ▼
[Этап 5: Облачная синхронизация] ──> [Этап 6: Тестирование и калибровка]
                                                      │
                                                      ▼
                                       [Этап 7: Деплоймент и публикация]
```

### Этап 1. Предпроектный анализ и сбор исходных геоданных
* **Задачи:** Изучение картографических материалов ГПЗ «Эбита», инвентаризация квартальной сетки Тереклинского и Эбитинского секторов, систематизация списка фауны млекопитающих и ландшафтных биотопов региона.
* **Использованные технологии:** Анализ спутниковых снимков высокого разрешения, оцифровка растровых схем границ, JSON-форматирование первичных данных.

### Этап 2. Проектирование архитектуры и структуры данных
* **Задачи:** Разработка схемы данных полевого наблюдения (`Observation Schema`), структуры векторного описания кварталов, выбор архитектурного паттерна *Offline-First*.
* **Использованные технологии:** Спецификация GeoJSON (RFC 7946), JSON Schema, структура коллекций NoSQL Firestore.

### Этап 3. Разработка картографического ядра и математических алгоритмов
* **Задачи:** Интеграция спутниковой подложки, реализация алгоритмов пересчета растровых координат в WGS 84, создание механизма топологического замыкания полигонов (Snapping) и автоматического построения периметра.
* **Использованные технологии:** Leaflet API, методы вычислительной геометрии (Point-in-Polygon, Union-Find, проекция точки на вектор).

### Этап 4. Разработка пользовательского интерфейса (UI/UX)
* **Задачи:** Создание адаптивного интерфейса полевого регистратора: модальные окна ввода данных, журнал наблюдений с фильтрацией, каталог биотопов, мобильная адаптация для смартфонов и планшетов.
* **Использованные технологии:** React 18, Tailwind CSS, Lucide Icons, HTML5 Canvas/FileReader.

### Этап 5. Реализация подсистемы хранения, авторизации и синхронизации
* **Задачи:** Настройка локального кеширования в браузере, интеграция облачной базы данных, настройка Google OAuth авторизации и ролевого доступа.
* **Использованные технологии:** Web Storage API (`localStorage`), Google Firebase (Firestore, Auth), правила безопасности Firestore Security Rules.

### Этап 6. Тестирование, калибровка и верификация
* **Задачи:** Полевое и камеральное тестирование точности геопривязки полигонов кварталов, проверка работы приложения без интернета (offline mode), стресс-тестирование экспорта в QGIS.
* **Использованные технологии:** QGIS 3 (для верификации экспортированных GeoJSON), Chrome DevTools (Network Offline Emulation, Performance Profiling).

### Этап 7. Сборка, непрерывная интеграция и публикация (CI/CD)
* **Задачи:** Оптимизация сборки проекта, настройка автоматического пайплайна развертывания и публикация в глобальной сети.
* **Использованные технологии:** Vite Bundler, Git, GitHub Actions Workflow, хостинг GitHub Pages, протокол HTTPS.

## Заключение
Разработанная геоинформационная система «ЭкоКарта Заказника Эбита» объединяет в себе функции полевого мобильного регистратора-навигатора и камеральной настольной аналитической ГИС. Применение связки React, Vite, Leaflet и Firebase с локальным хранилищем обеспечивает высокую производительность, отказоустойчивость в полевых условиях без интернета и удобство экспорта научных данных в форматы QGIS и Excel.
